## User journey

Send `POST JOB` to the configured Aadhyant WhatsApp sender. Explicit aliases `POSTJOB`, `POST_JOB`, `POST VACANCY` and `NEW VACANCY` are accepted. The English session reply links to `/post-job/`, where Company and Contractor have separate entry buttons and existing registration links. The chosen complete canonical vacancy form opens directly when the browser already has an active authorised session. Otherwise the existing portal login resumes that fixed form after the authoritative account-context check. No caller-controlled return URL is accepted.

This is an authenticated portal form reached from WhatsApp, not a passwordless Meta Flow. A phone message does not establish Company/Contractor ownership or create an account. The signed-in portal account and existing membership/management checks establish ownership. A link can be forwarded safely: it grants no vacancy authority. New or inactive employers still follow existing onboarding/approval. The same form includes the current dropdowns, compensation, facilities, benefits and candidate terms; no parallel form or recruitment storage was created.

The employer must explicitly Save or Submit for Review. Opening the link does not write a vacancy. Company submissions use the existing `manage_company_portal_requirement` workflow; Contractor submissions retain the existing managed-vacancy RPC and submission-idempotency contract. The Company write handlers additionally ignore concurrent duplicate clicks. Submitted jobs remain private drafts pending Admin review. This feature neither auto-approves nor publishes vacancies and does not bypass candidate alert consent, template, sender, scheduler, quota or publication-deduplication gates.
