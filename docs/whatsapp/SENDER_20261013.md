# Console sending and replies — reviewed implementation

Requested on 13 October after live Meta template sync succeeded. This extends the deployed console without replacing its canonical contacts, campaigns, recipients or outbox.

## Implemented

- Sender setup is admin authenticated, reads the configured WABA's phone list, and saves only a unique or explicitly configured owned phone ID. Requires the Meta access token, account ID, App Secret and webhook verify token. Multiple phones require an explicit `WHATSAPP_PHONE_NUMBER_ID`. No connection check sends a message.
- Sender has custom authentication: a verified admin session plus production origin and exact campaign ID, or the scheduler's server-only shared secret. It accepts no destination/template override. Worker batch is bounded to 10 and uses canonical leases. Source must deploy with gateway JWT verification disabled because it verifies the admin session or worker key itself.
- The canonical claim checks current consent, application/job eligibility, campaign ownership and unchanged approved template. The final provider boundary locks the outbound, campaign, template and configuration; it rechecks phone/account identity, readiness, consent, cancellation and job/application eligibility. Transaction checks do not claim atomicity across the later HTTP call.
- One Meta attempt per claimed record sends the actual two job parameters and exact Interested / STOP quick replies. Only a provider ID and a durable database receipt count as sent. Timeouts, invalid success bodies and unconfirmed receipts require reconciliation; they are never automatically retried. Explicit provider rejection is terminal. No provider body, token or raw destination is returned/logged.
- Restored webhook requires raw-body HMAC plus the exact configured WABA and phone ID. Verification GET uses the existing server verify token. STOP changes suppression; exact Interested is correlated to the original provider message and canonical recipient. Existing registered-candidate application creation remains delegated to the established function. Unregistered interest is recorded as registration required; it does not invent a Candidate or Application and does not automatically send a registration form.
- Reports include a bounded masked Replies view. Send Now queues the approved canonical campaign then processes its batches; Process Pending resumes only unprocessed sendable records. Automatic Schedule is explicitly disabled until a background scheduler is installed. This change does not enable the retired scheduler.
- Sender configuration and template freshness expire after 24 hours. Verify the connection and sync templates again if either expires. No readiness value is set by this migration.
